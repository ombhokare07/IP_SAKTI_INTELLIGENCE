# Dataset and Source Policy

IP-SAKTI keeps authoritative evidence, operator-supplied local corpora, and synthetic fixtures separate. A filename or bundled record is never treated as proof of authenticity.

## Bundled content

| Path | Role | Authority status |
| --- | --- | --- |
| `data/raw/india/patents/ayush_patent_guidelines_2025.pdf` | Source PDF preserved from the supplied base project for local RAG ingestion/tests. | Locally supplied document. Its title, edition, provenance, currency, and legal effect must be verified by the operator before substantive use. |
| `data/fixtures/tk.json` | Offline Phase-3 workflow fixture. | Synthetic test data; not TKDL and not evidence of clearance. |
| `data/fixtures/regulations.json` | Offline Phase-5 workflow fixture for India/USA/EU/UK. | Synthetic test data; not current official regulatory text. |
| `data/test_data/*.json` | Preserved test-data placeholders from the base structure. | No substantive authority content. |

Mock prior-art records are generated by `MockPriorArtProvider` only when explicitly enabled. They use unmistakable test identifiers/labels and cannot support a novelty conclusion.

## Live/provider evidence

- EPO OPS results are accepted only through the configured OAuth adapter and retain provider identifiers and retrieval metadata.
- Generic prior-art, TK, regulation, translation, and voice HTTP interfaces are operator-managed gateway contracts. They do not imply an authority offers that interface.
- A TK corpus may be searched only after the operator configures it and asserts authorization. No TKDL content or access mechanism is bundled.
- Regulatory gateways should return the issuing authority, jurisdiction, title, version/effective dates, actual source URL, excerpt, and retrieval timestamp. Missing provenance lowers or prevents evidence sufficiency.

Configured provider status means configuration is present, not that the source has been authenticated. Operational and source verification requires a successful request and human review.

## Citation rules

Evidence records require a stable identifier, title, excerpt, mode, and a retrievable locator or HTTPS source URL where applicable. Page numbers are one-based. The Phase-1 PDF pipeline preserves filename, resolved local path, page, and deterministic chunk identity.

The application does not invent source pages, URLs, patent identifiers, authority names, or retrieval success. Invalid and unlinked citations are rejected.

## Adding a local corpus

1. Obtain and document legal authorization to use the corpus.
2. Store it outside source control and the distributable archive.
3. Validate the required schema and provenance fields.
4. Configure its path through `.env` (`TK_CORPUS_PATH` or `REGULATION_CORPUS_PATH`).
5. For TK, set `TK_SEARCH_AUTHORIZED=true` only when authorization is real and current.
6. Perform a test query and inspect the returned evidence and provider mode.

Do not replace a fixture with copied live content while retaining `mock` labels, and do not remove mock labels from synthetic content.
